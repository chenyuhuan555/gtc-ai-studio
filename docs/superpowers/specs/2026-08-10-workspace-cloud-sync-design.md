# GTC AI Studio 工作区云同步设计

## 目标

在保留现有 React + FastAPI 结构的前提下，把 Dashboard、聊天历史、表单草稿和最近生成记录从浏览器专属数据升级为可跨设备恢复的工作区数据。品牌知识库、案例库和 Prompt 历史继续使用现有独立业务表。

## 方案

- 保留现有 FastAPI 作为业务 API 和 AI 服务入口。
- 生产数据库使用 Supabase PostgreSQL。
- 新增 `workspace_state` 表，以一个 JSONB 快照保存第一阶段的工作区状态。
- 前端继续以 localStorage 作为本地缓存和断网兜底；云端作为跨设备持久化源。
- 同步采用版本号乐观锁，保存时带 `expected_version`，版本不匹配返回冲突，不静默覆盖。
- 同步接口必须在生产环境启用登录身份校验；不能使用公开的固定工作区密钥代替用户认证。
- DeepSeek API Key 不写入云端快照，继续保留在浏览器本地。

## 数据边界

云端快照包含：

- Dashboard 任务、日历和内容表现数据；
- AI 助手会话历史；
- 内容生产中心和 Prompt 表单草稿；
- 最近生成记录；
- 非敏感的模型设置。

继续使用独立业务表：

- `brand_info`；
- `brand_rules`；
- `content_cases`；
- `platform_rules`；
- `prompts`。

不上传：DeepSeek API Key、服务端连接串和其他凭据。

## 同步流程

1. 应用启动先读取 localStorage，保证页面可用。
2. 用户完成登录后拉取云端工作区。
3. 云端没有数据时，仅把本地数据作为首次初始化数据上传。
4. 云端已有数据时，按版本和更新时间判断；不允许旧云端快照无条件覆盖本地新数据。
5. 用户修改工作区后，先写本地，再以约 1 秒防抖写云端。
6. 版本冲突时保留本地状态并显示同步失败状态，后续再加入明确的冲突合并界面。

## 第一阶段不做

- 实时订阅；
- 每张业务表拆分同步；
- 文件 Storage 同步；
- 离线写队列；
- 复杂多租户权限模型。

## 验收标准

- 后端能创建和读取 `workspace_state`。
- 同一工作区的版本冲突不会覆盖较新的数据。
- 前端无云端配置时仍可使用本地模式。
- 前端开启同步后，刷新页面能够恢复工作区状态。
- 未配置认证时，同步接口不会以生产模式公开读写。
- 现有后端接口和前端构建不回归。
